# SmartMeds — Manual Setup Guide

This covers everything you need to do by hand to go from "files placed in
folders" to "app runs and talks to a real Supabase backend." Follow in
order — later steps depend on earlier ones.

---

## Step 1 — Create the actual Flutter project

The files you have are source code, not a runnable Flutter project by
themselves — you need Flutter's own scaffolding (android/, ios/, etc.)
around them.

```bash
flutter create smartmeds
cd smartmeds
```

This generates a fresh project with its own `android/`, `ios/`, `lib/`,
`pubspec.yaml`, etc.

Now:
1. **Delete** the generated `lib/main.dart` and `pubspec.yaml`
2. **Copy in** everything I gave you:
   - Your `lib/` folder (all of it) → replaces the empty one
   - Your `pubspec.yaml` → replaces the generated one
   - Your `supabase/` folder → place at the project root, alongside `lib/`
   - Your `README.md` → project root

Your project root should now look like:
```
smartmeds/
├── android/          ← generated by flutter create, don't touch
├── ios/               ← generated by flutter create, don't touch
├── lib/                ← your code
├── supabase/          ← your SQL + edge function
├── pubspec.yaml       ← yours
└── README.md
```

## Step 2 — Install dependencies

```bash
flutter pub get
```

If this errors on version conflicts, run `flutter pub outdated` and adjust
version numbers in `pubspec.yaml` — some package versions may have moved
on since this was written.

---

## Step 3 — Create your Supabase project

1. Go to [supabase.com](https://supabase.com) → sign up / log in
2. **New Project** → pick a name, a database password (save it somewhere),
   and a region close to you
3. Wait ~2 minutes for it to provision

---

## Step 4 — Run the SQL migrations, IN ORDER

Go to your Supabase project → **SQL Editor** → **New Query**. Run each
file's contents as its own query, **in this exact order** (each depends on
tables the previous one created):

1. `supabase/002_medicines_table.sql`
2. `supabase/003_reminders_table.sql`
3. `supabase/004_prescriptions_table.sql`
4. `supabase/005_family_profiles.sql`

For each: open the file, copy the whole contents, paste into a new SQL
Editor query, click **Run**. Check for a green success message before
moving to the next one.

**Note on migration 005 specifically:** it includes a data backfill script
(creates a "Myself" profile for existing users). Since you're starting
fresh with no existing data, this will just run harmlessly with nothing to
backfill — no action needed, just run it like the others.

You do **not** need to run anything manually for Row Level Security or
storage buckets — the migrations create those automatically as part of
running the SQL.

---

## Step 5 — Get your Supabase credentials

In your Supabase project → **Settings** → **API**:
- Copy the **Project URL**
- Copy the **anon / public key** (NOT the `service_role` key — never put
  that one in the app)

---

## Step 6 — Put the credentials into the code

Open `lib/core/services/supabase_service.dart` and replace:

```dart
static const String supabaseUrl = 'https://YOUR_PROJECT_ID.supabase.co';
static const String supabaseAnonKey = 'YOUR_SUPABASE_ANON_KEY';
```

with your actual values from Step 5.

---

## Step 7 — Configure Auth redirect URLs

In Supabase → **Authentication** → **URL Configuration** → **Redirect URLs**,
add:
```
io.smartmeds.app://email-verified
io.smartmeds.app://reset-password
```

These are needed for email verification and password reset links to be
accepted by Supabase, even though deep linking isn't fully wired on the
app side yet (see the README's Module 4 notes — verification still works
via the in-app polling check either way).

---

## Step 8 — Android platform permissions

Open `android/app/src/main/AndroidManifest.xml`. Inside the `<manifest>`
tag (as a sibling of `<application>`, not inside it), add:

```xml
<uses-permission android:name="android.permission.POST_NOTIFICATIONS"/>
<uses-permission android:name="android.permission.SCHEDULE_EXACT_ALARM"/>
<uses-permission android:name="android.permission.RECEIVE_BOOT_COMPLETED"/>
<uses-permission android:name="android.permission.CAMERA"/>
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES"/>
```

Save the file.

---

## Step 9 — iOS platform permissions

Open `ios/Runner/Info.plist`. Inside the outermost `<dict>`, add:

```xml
<key>NSCameraUsageDescription</key>
<string>SmartMeds needs camera access to photograph prescriptions and lab reports.</string>
<key>NSPhotoLibraryUsageDescription</key>
<string>SmartMeds needs photo library access to attach existing prescription images.</string>
```

Then, in Xcode (open `ios/Runner.xcworkspace`, not the `.xcodeproj`):
- Select the **Runner** target → **Signing & Capabilities**
- Click **+ Capability** → add **Push Notifications**
- Click **+ Capability** → add **Background Modes** → check **Remote notifications**

(Skip this whole step if you're only testing on Android for now.)

## Step 11 — Test the core flow, in this order

1. **Register** a new account with a real email you can check
2. Check your inbox, click the verification link (it'll open in a
   browser — that's expected, not broken)
3. Come back to the app — the verification screen polls automatically
   and should move you to Login within a few seconds
4. **Log in**
5. You'll land on an empty Dashboard — this is expected, there's no data yet
6. Tap **Add Medicine** (the FAB) → fill in a name, dosage, quantity → save
7. Open the medicine → **Manage Reminders** → add a reminder time (pick
   "Morning" or a custom time a couple minutes from now, to test quickly)
8. Go back to the Dashboard, pull down to refresh — your medicine should
   now show up under "Today's Medicines"
9. Wait for the reminder time (or just tap **Take Now** directly from the
   Dashboard) — confirm the dose
10. Open the drawer (☰ icon top-left) and click through each section —
    Progress, Statistics, History, Stock, Prescriptions, Family Profiles,
    Accessibility, Settings — to confirm they all load without crashing

If registration fails immediately with a network-looking error, the most
common cause is a typo in the URL/key from Step 6 — double-check there's
no trailing slash on the URL.

## Step 12 (optional, later) — Deploy the delete-account function

This is **not required to run and test the app** — only needed if you
want the Delete Account button in Settings to actually work. Skip this
until you need it.

1. Install the Supabase CLI: `npm install -g supabase`
2. `supabase login`
3. `supabase link --project-ref YOUR_PROJECT_ID` (find your project ref
   in the Supabase dashboard URL)
4. Set the service role key as a function secret:
   ```bash
   supabase secrets set SUPABASE_SERVICE_ROLE_KEY=your_service_role_key
   ```
   (find this in Supabase → Settings → API → `service_role` key —
   this is the ONE place it's safe to use it, since it stays server-side)
5. Deploy: `supabase functions deploy delete-account`

Until you do this, tapping "Delete Account" in the app will show a clear
error message rather than silently failing or crashing.

## Things that will NOT work yet, even after all of the above — by design

These are documented limitations from the build itself, not setup
mistakes on your part:

- **History, Calendar, and Progress's Weekly/Monthly tabs** show combined
  data across all family profiles, not filtered to whichever profile is
  selected (flagged in Module 11's README section)
- **Notification Sound / Reminder Volume** in Settings are stored but
  don't actually change anything audible yet (Module 16's README section)
- **Language** picker only functions for English; others are visibly
  disabled
- **Offline mode** only caches medicines and today's doses — History,
  Calendar, Statistics, and Prescriptions require a live connection
  (Module 15's README section)
- **Caregiver alerts** only fire while the app is open and being used —
  there's no background server checking for missed doses independently
